## What the gate found (all fixed, each with a test that fails without the fix)

- **A task never waited for the person.** `needs_human` was recorded as a failed step and the session moved on; the person's yes then ran `apply_skill` after the session ended, and the landing refused the file it left. Task sessions now wait through the question (`orchestration/session.py`); chat still moves on.
- **A skill applied in a worktree was loaded from the live tree** and refused as "not a file". It loads from the worktree now.
- **A restart waited out the dead process's lease** (600 s) before resuming a task. In single mode Planning releases leases found at boot.
- **A resumed session counted one step short** (the `worktree_open` step is recorded before `task.started`), so it wrote a second "step 2".
- **Gemini's key in `secrets.toml` never reached the provider**, and its thinking tokens ate the answer's budget and went unbilled.
- **Two "flaky" tests were real races**: two acquisitions of one skill both registered it; a slow first TV video download played over a later request. A third was a test script that assumed Sim always answers within 450 ms.
- **Harness**: trials now take spend caps, print why a task blocked, and have a stand-in person (`person_answers`) because installing a skill always asks a human now.
