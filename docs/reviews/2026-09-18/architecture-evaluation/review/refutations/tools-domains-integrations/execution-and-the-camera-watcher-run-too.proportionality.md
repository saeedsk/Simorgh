**reasoning:** The mechanical claim is verified: Execution's boot autostarts and the camera watcher call tool.run() directly with synthetic action ids, with no action.proposed, no Guardian decision, no token, and no action:* stream. But three of the sub-claims that carry the 'high' severity are wrong on this machine and in this code: (1) 'casting to the TV at boot' does not happen -- tv_show_on_start defaults False (execution/config.py:466, deliberately turned off 2026-09-17 per the comment) and ~/.simorgh/simorgh.toml [execution] does not set it, so _autostart_tv_show returns at the first guard; (2) 'a paid-model spend with no BudgetRule' is false -- images are routed only to providers declaring supports_images, and only the Ollama provider does (grep shows supports_images exists solely in cognition/providers/ollama.py; toml sets vision_model = 'qwen2.5vl:3b'), so the per-motion-event vision call is local and free, every call is recorded in cognition:calls (9,379 events) and the cognition:budget:ollama stream, and Guardian's BudgetRule would abstain anyway because it only fires for draft_patch/draft_skill/review (rules.py:703); (3) 'the ledger never records' is overstated -- the bus TraceWriter defaults to rate 1.0 for unlisted types, and 11,536 trace streams contain world.camera.event and 1,516 contain a cognition.think with images. The honest caveat is that trace: streams have a 2-day retention (ledger/compaction.py:36) so this record is ephemeral while action:* streams are permanent. The site count is also inflated: vision.py:235 is inside CameraDescribeTool.run and reuses the caller's ctx, i.e. tool composition under an already-approved action, not a bypass; the real bypass sites are the four in service.py plus vision.py:475 (cam_list/ring_list, both read_only) and :515 (cam_snapshot/ring_snapshot). What survives: the docstring invariant ('Guardian sees every call') is false for these six sites; routing through Guardian would have given the PausedRule/ModeRule gates -- today a paused or locked system still snapshots cameras and calls the vision model because on_camera_event checks only config.camera_vision (vision.py:302) and the autostarts never consult self._paused; and the permanent action record does under-count camera use (though the same record is 85% ring_live dashboard offers, 22,849 streams, so it already misrepresents 'what the cameras did'). Through the scale lens: the bypassed tools are pollers, listings and a still-to-disk -- none is the siren, light or PTZ, which remain proposal-only -- and the origin of a boot proposal would resolve to 'human' (guardian/service.py:244-248) and be auto-allowed as reversible in guarded mode, so the fix adds a record and the paused/locked gate, not a human check. The recommendation is cheap and worth doing for the invariant's sake, but it is a medium 'design undermined by a shortcut' finding, not a high one, and the why_it_matters paragraph should be rewritten without the boot-cast and paid-spend arguments.
