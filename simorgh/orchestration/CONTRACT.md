# orchestration -- contract

One-line status: layer X · 5,664 lines · 30 test files · lock: `orchestration` in docs/modules/locks.toml

## Purpose

Orchestration owns the agent loop: it claims a task (or takes a conversational percept), runs one `Session` through gather, think, propose, verify, and reports one terminal outcome (`task.completed|failed|blocked|paused` plus `turn.completed`). It owns the per-kind `Profile` table (which tools a session may *request*, step and revision caps, scaffold), the prompt's `task_rules` scaffold, the memory and conversation blocks of every think, and the tree hygiene around code tasks (worktree open, land, close; discard of uncommitted edits). It must never run a tool itself or decide whether one is allowed: every tool call becomes an `action.proposed` and Guardian is the sole authority. The one decision that shapes it: the session is a bus-driven state machine that talks to Cognition, Guardian/Execution, Memory and Verification only by request/reply and correlated events, and records every step on the `task:<id>` ledger stream so a second worker can resume it (`resume.py`).

A background report delivered to its person is recorded first as `crew.message{from: <member>, to: "<channel>:<person>", kind: "report", body: <summary>}` (`crew.DELIVERED_KIND`); `Crew.fold` rebuilds `Crew.delivered` from it. On start, `Service` asks one Worker for `SessionRunner.deliver_pending_background`: every `crew:` stream (`ledger.streams("crew:")`) with a background member is folded, and each background member with a filed report and no such record is delivered now, through `_deliver_to`; a second start finds the records and delivers nothing. Only a report filed within `session.PENDING_WINDOW_S` (24 h) is delivered, and a crew whose last event is older is skipped without a full read: a crew delivered before the record existed (before 2026-10-27) has none, and must not be said again on the first start after the upgrade. A crew started from outside is marked `external: true` on its `crew.spawned` and is never turned into a notice.

`crew:<id>` holds the four `crew.*` topics plus two stream-only types: `crew.member.status{handle, status, reason?}` (a member's status, and the root's own `waiting`/`running` around `await_agents`, whose `reason` is `{"await": {handles, mode, timeout_s}}` so a restarted root re-enters it) and `crew.board{handle, key, value}`.

Also written: blobs (`ledger.put_blob`) for the verify subject (`session.py:1905`), plan artifacts (`worker.py:444`) and oversized result text (`worker.py:569`). `person:<name>` and `someone:` in this package are memory tags and room-text markers, not streams.

`ablate` switches guardrails off for the stage 14 ablation matrix (docs/plan/stage-14-toolchain-evals-and-ablation.md). The guardrails (stage 16, docs/plan/stage-16-forge-guardrails.md, `guardrails.py`), on by default:
- At the proposal point, before any `action.proposed`, the calls the step would run are validated: a tool the last think did not offer is `unknown_tool`; arguments that are not an object, a native call's decode `error`, or arguments failing the top-level part of the tool's `input_schema` that Guardian enforces (required, narrowed for a marker tool; kind, with Guardian's widening) are `bad_args`. Both ride the tool channel (a `tool` message answering the call, for a native call). Nothing else is pre-filtered: every surviving call is proposed and gated, and a Guardian denial is fed back as before -- never a nudge, never retried.
- A text reply is an answer (ADR-013). It is nudged (`retry`, a `user` message) only when it names an offered tool directly followed by `(`, `{` or `[`, or holds a fenced JSON object whose `tool`/`name` key is an offered tool (JSON with any other `name` is an answer, not a call). In a chat or voice session (scaffold `chat`, `Guards.conversation`) only a reply that is nothing but that call-shaped text counts (`looks_like_call(whole=True)`: after think blocks and one surrounding fence it opens with `{`, `[`, `<` or an offered name and closes with `}`, `)`, `]` or `>`); prose around a quoted call is an answer, matching Cognition's whole-reply rescue for `purpose: "chat"` thinks (stage 16 review, 2026-10-27).
- `max_retries` consecutive nudges of those three kinds, then `failed` `retries exhausted: <kind>`; a clean proposal resets the count. `max_tool_errors` consecutive steps with a hard error (`error_kind = "failed"`), then `failed` `tool errors exhausted`; `transient` is not counted; a fully ok step resets it. A `refused` or `unconfigured` result for the same tool and arguments twice ends the session `blocked` (`the same call was refused twice`).
- Steps from the agent's frontmatter: a terminal call, or a final text answer, while a `required_steps` tool has not succeeded gets a `step` nudge at tier 1, 2, 3 (forge's polite / direct / "STOP"), then `blocked` `required steps not done: <pending>`; a call whose `prerequisites` have not run (ok, or a hard failure the tool reported) blocks the whole batch with a `prerequisite` nudge, and the third consecutive one is `blocked` `prerequisites not done: ...`. Shipped: `agents/patch.md` and `agents/skill.md` (and so `skill-writer`) carry `prerequisites = { git_commit = ["run_tests"] }`; nothing in `chat.md` or `voice_chat.md`.
- A nudge gives back the step its think took (`max_steps` is not spent), is recorded on `task:<id>` as a `task.step` with `nudge`, and is not counted by `resume.py`. Nudges run only before the last step. Prerequisites hold on the last step too (stage 16 review, decided 2026-10-27): the one finishing (`git_commit`, `git_discard`, with uncommitted edits) or durable (`apply_source_patch`, `apply_skill`) call that step would still run is checked by `Guards.check_last` / `Steps.check_last`; an unmet prerequisite is not proposed, nothing is counted, and the session ends `blocked` `prerequisite not done: <missing>` (`guardrails.PREREQUISITE_NOT_DONE`, `session.PREREQUISITE_REASON`), which `_continues` treats like a continuation, so the edits stay in the tree (or worktree) for the next attempt. Under `ablate = ["steps"]` the last step is as before. Step state lives on the session (`Session.guards.steps`), is written on each step as `steps_state`, and a crash-resumed session continues from it (`Session.step_state`).

There is no `lease_seconds` key: a task's lease is `[planning] lease_seconds`, carried on each `task.available` and read by `worker.py` from the payload. The unread copy here was removed on 2026-09-19, so writing it is now reported by `kernel/configcheck.py` as a section that changed nothing (`test_config.py`).

Tool routing (stage 17 items 3 and 6, docs/plan/stage-17-tool-routing-and-prompt-compression.md; `routing.py`, `SessionRunner._route_offer`). Only a person's own chat or spoken turn is routed (`kind == "chat"`, scaffold `chat`, depth 0, not a crew member); tasks, helpers and members are offered their whole agent list. `ablate = ["routing"]` is `off`.
- `off` (default): nothing is routed; the think payload (`tools`, `task_rules`, `messages`) is byte-identical to a build without routing, and `tool_more` is not offered (no agent file lists it).
- `shadow`: the turn is routed at its first think and offered everything, as `off`. At the turn's end a `routing.shadow` telemetry event (trace = the turn's) carries `offered` (routed groups), `used` (tools called, in order, without `tool_more`), `used_groups`, `missed` (used tools of the agent's own the route would not have offered: the miss rate's numerator; the crew, delegation and wait built-ins added after the route are never a miss), `more`, `conversational`, `tools_offered`, `channel`, and (2026-10-27) `embedder` (`memory:<model>/<dimension>`, `lexical` or `injected`: `Session.route_embedder`) and `fallback` (`Session.route_fallback`: why a turn that wanted Memory's embedder went lexical, "" otherwise). No bus topic for the event itself. `python -m simorgh.telemetry routing` reads these events (telemetry's CONTRACT.md): keep the attribute names in step with `telemetry/routing.py`.
- `on`: the model is offered `routing.tools_for(route + route_more)`: groups sorted by name, each group's tools in `groups.toml` order, then tools in no group (skills), so two turns routed alike send a byte-identical `tools` list and `task_rules`. The core group (`memory`: `remember`, `memory_search`, `memory_forget`, `tool_more`) is always in. The agent's other tools are not shown and stay callable: `guards.offered` (what `validate` accepts) is the whole list, a call to one is proposed to Guardian like any call, and its group is offered from the next step (`Session.route_more`). The same `routing.on` event as shadow is written at the end of the turn.
- `tool_more{group}` (Execution's `ToolMoreTool`, read-only, in `_TOOL_POLICY`): the group name is checked in the session (an unknown one is refused with the list and never proposed), the call is proposed to Guardian with `args = {group}` (a marker's `argument` is mapped), and only an approved call adds the group to the next step.
- A router that cannot decide never costs a turn: an unreadable `groups.toml` (read once per runner) or an embedder that raises offers the turn everything, as `off`, and writes a `routing.failed` telemetry event (`error`, `mode`); no `routing.shadow|on` event follows for that turn.
- Stickiness is per conversation (`transcript.conversation_id(channel, speaker)`), in the runner's memory: `route_sticky_turns` turns of used groups, lost on restart.
- The embedder (2026-10-27): Memory's configured one, over `memory.embed` (orchestration may not import `simorgh.memory`). The groups' utterances are embedded once, in the background, and kept per (model, dimension) (`SessionRunner._route_tables`); each routed turn's text is embedded within `route_embed_timeout_s` (0.3 s) at its first think (`_route_remote_turn`, before `_route_offer`) and scored against the utterance centroids (`aggregate="centroid"`). Anything short of that -- no table yet, Memory refusing (its embedder is hashing, or a model is loading), no answer in time, an error, a turn vector of another model than the table's (the table is then fetched again) -- routes that turn with `routing.lexical_embed` (hashed words and character trigrams, no model; a group scored by its nearest example, `"nearest"`) and records why in `Session.route_fallback`; it is never a `routing.failed` and never costs the turn. `SessionRunner(route_embed=)` still injects an embedder (centroid), and then Memory is never asked. With `tool_routing = "off"` nothing is asked and nothing is awaited: the think payload is unchanged.
